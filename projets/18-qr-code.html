Question 1

Combien de bits faut-il pour coder un message ?

Avec 1 bit (0 ou 1), on distingue 2 messages ; avec 2 bits, 4 ; avec 3 bits, 8… Chaque bit double le nombre de possibilités. Pour distinguer N messages, il faut donc au moins log₂ N bits : autant que de questions oui/non pour deviner le message.

Les maths derrière : le binaire et le logarithmen bits ⟷ 2n messages · N messages ⟶ log₂ N bits

Pour 26 lettres, il faut au moins log₂ 26 ≈ 4,7 bits, donc 5 bits par lettre avec un code de longueur fixe.

📖 Dans le livre : ch. 18, Station 1 : binaire et logarithme, p. 167
Chaque bit double les possibilités

Question 2

Qu'est-ce qu'un bon code ?

Un code où deux messages différents donnent toujours deux codes différents : sinon, on ne saurait pas quoi décoder. Et le décodage doit redonner exactement le message de départ.

Les maths derrière : injection et rétractiondécoder ∘ encoder = identité

L'encodeur est une fonction injective ; le décodeur en est une rétraction : appliqué après l'encodeur, il ramène au point de départ.

φ Morphisme : l'encodeur est injectif, le décodeur le défait 📖 Dans le livre : ch. 18, Station 3 : encodeur, décodeur, p. 168
Aller-retour sans perte

Question 3

Peut-on faire des codes plus courts ?

Oui, en donnant des codes courts aux symboles fréquents et des codes longs aux symboles rares, comme le morse donne un seul point au « E ». Si un symbole sort une fois sur deux, on lui donne 1 seul bit.

Les maths derrière : le codage de HuffmanA → 0 · B → 10 · C → 110 · D → 111

Aucun code n'est le début d'un autre : on peut décoder une suite de bits sans séparateur.

📖 Dans le livre : ch. 18, cas concret « QR code et compression audio », p. 171
Le plus fréquent a le code le plus court

Question 4

Jusqu'où peut-on compresser sans rien perdre ?

Il existe une limite infranchissable, calculée par Claude Shannon en 1948 : l'entropie. Pour nos quatre symboles, elle vaut 1,75 bit par symbole, contre 2 bits pour un code de longueur fixe. Le code de la question précédente atteint exactement cette limite : 12,5 % de gagné.

Les maths derrière : l'entropie de ShannonH = −Σ pi log₂ pi = 1,75 bit

0,5 × 1 + 0,25 × 2 + 0,125 × 3 + 0,125 × 3 = 1,75. Aucun code sans perte ne peut faire mieux en moyenne.

📖 Dans le livre : ch. 18, Station 3 : l'entropie de Shannon, p. 166
Bits par symbole, en moyenne

Question 5

Comment un code peut-il résister à une tache ?

En faisant l'inverse de la compression : on ajoute volontairement de la redondance. Idée la plus simple : envoyer chaque bit trois fois (0 → 000) et prendre la majorité. Si un bit est abîmé (010), on retrouve quand même 0.

Les maths derrière : la redondance0 → 000 · reçu 010 → majorité : 0

On paie la fiabilité en longueur. Les vrais codes correcteurs sont bien plus économes que la simple répétition.

📖 Dans le livre : ch. 18, Ouverture : un carré noir et blanc, lisible même abîmé, p. 167
La majorité l'emporte
6
Question 6

Comment fait le QR code ?

Il utilise un code correcteur bien plus malin, dérivé des codes de Reed–Solomon. Le message est encodé avec de la redondance organisée, de sorte que jusqu'à 30 % des petits carrés peuvent être illisibles. On peut même y coller un logo !

Les maths derrière : les codes correcteursjusqu'à ≈ 30 % de modules perdus

Un QR code « haute correction » contient nettement plus de bits que le minimum donné par l'entropie : c'est le prix délibéré de la fiabilité.

📖 Dans le livre : ch. 18, cas concret, le QR code, p. 171
Lisible malgré la tache

Question 7

Et pour compresser une chanson ?

Deux étapes. Sans perte, on applique l'idée de Huffman aux motifs sonores fréquents. Puis le MP3 ou l'AAC vont plus loin : ils suppriment des fréquences que l'oreille ne perçoit pas. On ne retrouve plus le signal exact, mais une version impossible à distinguer à l'écoute.

Les maths derrière : compression avec et sans pertesans perte : décoder ∘ encoder = id · avec perte : ≈ id

Avec perte, le décodeur n'est plus une rétraction exacte : c'est un compromis jugé acceptable par l'oreille.

📖 Dans le livre : ch. 18, cas concret, « compression avec et sans perte », p. 171
Taille du fichier (ordre de grandeur)

Question 8

Compression et correction, ce n'est pas contradictoire ?

Si, et c'est tout l'art du codage ! La compression retire la redondance inutile, la correction en remet une, mais organisée et choisie. Un bon système fait les deux : il compresse d'abord, puis protège le résultat.

Les maths derrière : l'équilibre entre entropie et redondancemessage ⟶ compresser ⟶ protéger ⟶ envoyer

C'est ce que font la radio numérique, les téléphones et les sondes spatiales.

📖 Dans le livre : ch. 18, Coder l'information, p. 165
